## D1 hcasmc 的排除理由比 Q3 的字面写法更宽（看到计数后、看到任何指标前）
- Q3 原文：hcasmc 的 `.hdf5` 若「无法按块读取（内存或格式问题）」，按可行性排除。
- 实际情况：文件可以按块读取（峰值内存 0.3 GB），但里面只有 62,710 个 RNA 基因，没有任何 guide 特征，也没有每个细胞的 guide 分配，所以无法判定细胞受了哪个扰动。
- 主控独立核实（16:46–16:49）：
  1. 直接读 `IGVFFI5999NXAF.h5` 的结构：只有 `cells / genes / data / indices / indptr / shape`；
  2. 通过 IGVF 公开 API 列出分析集 `IGVFDS6248NDUW` 的全部 5 个文件；
  3. 用 HTTP 分段读取（不下载矩阵）检查带注释的 `IGVFFI9007DBZO.h5ad`（87.29 GB）：`obs` 只有 sample、species、gene_count、tscp_count、mread_count、leiden，同样没有 guide 分配；
  4. guide 信息只存在于 gRNA 测序原始 FASTQ（每个子文库约 15 GB，共 14 个），要用 Parse 的组合条形码流程从头处理，超出 80 GB 预算，且引入新的未预注册处理步骤。
- 结论：hcasmc 按可行性排除，理由写作「公开数据未提供每个细胞的 guide 分配」。这个决定只依据文件结构，与任何结果无关。

## D2 telohaec 未过门槛的核查（不是偏差，只是记录）
- telohaec 只有 17/2,198 个靶点在本线上可重复，进入评测的靶点 9 个（< 50）。数据筛查曾估计 75–149 个。
- 主控检查了是否是流程错误（只看 QC 量，不看任何预测或评测指标）：
