## Amendment CB1.2a (2026-11-27 10:14 +0800, controller; before any code freeze and before any real-target inference)
CB1.2(a) above required each pair's own masked matched arm to pass **validity or positivity**. The positivity part was a controller error. In the PREREG_I / Addendum A H-I1 cascade, positivity of the matched arm is a **line-level** gate. It is the one that separates `LINE_EQUIVALENT_NULL_SIGNAL` from the non-zero-signal outcomes. Per-source categories need only validity. Requiring positivity per pair would make a null-signal line's masked pairs always `INCONCLUSIVE`, removing an outcome the cascade allows.

**Corrected CB1.2(a):** a pair's common-axis category is `INCONCLUSIVE` if its own masked matched arm fails **validity** (valid_frac ≥ 0.95 and ρ_ab_orth > 0, with finite 97.5% bounds). Positivity is not checked per pair. Positivity enters only through the line-level gate of CB1.2(b), the primary rhj_6983_axis matched arm. CB1.2(b) and (c) are unchanged.
