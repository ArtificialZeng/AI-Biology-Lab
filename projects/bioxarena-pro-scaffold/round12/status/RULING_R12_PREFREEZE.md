## 裁定 B：HEK293 不设线粒体比例上限
- **结论：** `hek293_xucao` 的主分析**不使用** `max_pct_mt = 20` 过滤（关闭该过滤，等价于 `max_pct_mt = 100`）。
- **理由：**
  1. PREREG_E §3.2 对 HEK293 的细胞筛选写得很具体：作者的单 sgRNA 规则，加上 ≥ 300 个 RNA UMI、≥ 200 个基因，并要求「保留全部 QC 合格的单 sgRNA 细胞」。里面**没有**线粒体比例上限。
  2. `max_pct_mt = 20` 是从第十一轮 10x 读取代码继承来的**代码默认值**，不是预注册规则。预注册文本和代码默认值冲突时，以预注册文本为准。
  3. 这个过滤会去掉 75,452 / 98,315 个细胞（76.7%），等于在没有预注册的情况下大幅改变样本。
- **主控独立核对的元数据（`python3 -I`，只读 obs）：**
  - 98,315 个细胞，2,758 个 NTC（`perturbation == control`）；
  - `nperts` 只有 0 和 1，说明导出文件已经是单 sgRNA 细胞；
  - 全部细胞都满足 ≥ 300 UMI 和 ≥ 200 个基因；
  - `percent_mito` 的 5/25/50/75/95 分位数为 12.9 / 19.9 / 25.8 / 32.3 / 42.4%；
  - 203 个靶点，其中 195 个有 ≥ 25 个细胞；
  - obs 里没有重复或批次列，所以按 §3.2 第 2 阶段，用 seed 42 分层对半分。
- **不新增 MT ≤ 20% 的敏感性分析。** 原因是避免在锁定之后增加未经预注册的分析分支。线粒体比例的分布作为披露信息写进 QC 文件和最终判定。
- A549 不受影响：作者已经过滤到 mt < 10%（最大值 9.994%），20% 的上限在 A549 上去掉 0 个细胞（`n_pre_qc_kept == n_qc_kept`）。

## 裁定 A：冻结前必须修的代码错误（不改算法）
1. **HEK293 索引读取（A-T2 和 A-T3 都要修）。**
   - AnnData 0.2.0 把 obs 和 var 的索引列名放在 `group.attrs["_index"]` 里（本文件分别是 `cell_barcode` 和 `gene_symbol`）。
   - `round12/src/dataset_readers_r12.py` 和 `round12/audit/independent_r12_loader.py`（第 834–845 行）都只找名为 `_index` 或 `index` 的数据集，找不到时退回 `cell_{i}` 或 `G{i}` 这样的合成名字。
   - 后果：§3.2 第 2 阶段要求的「按条形码排序后再分半」会用错顺序，基因名也会全部丢失。
   - 改法：先读 `attrs["_index"]` 指向的列，再兼容 `_index` 和 `index`。**HEK293 找不到真实索引时直接报错，不允许退回合成名字。**
2. **A549 int32 溢出（A-T2）。**
   - `dataset_readers_r12.py:424` 改成 `csc_b.indptr[1:].astype(np.int64)`。
   - 原因：GSE345058 有 3,598,670,133 个非零值，超过 2^31 − 1。
3. **HEK293 的 MT 过滤（A-T2）。** `build_hek293_parts` 的 `max_pct_mt` 默认值改为不过滤（`None` 或 100），并在代码注释里引用本裁定。
