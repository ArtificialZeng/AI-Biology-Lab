# 第九轮多智能体协作规则（所有 Antigravity 侦察员必须遵守）

主控：Claude ｜ 人类：Zijian Zeng ｜ 目标：找到并做出**确认没人解决过**、能投 Nature / Science 及其子刊的科研发现。

## 你是谁
你是第九轮的「侦察员」之一。每个侦察员负责一个方向，互不重叠。你的任务卡在 `round9/cards/<你的编号>.md`。
这一阶段**只筛题和查新，不攻题**。攻题等主控核验后另行分派。

## 为什么这么严
第七、八轮做完才发现，核心结论 Miller 等（Nature Biotechnology 2026）已经发表。v1 预印本里还出现过张冠李戴和「XX Authors」这样的参考文献。所以这一轮：**每一条「没人做过」都要有检索记录，每一篇文献都要用 API 核实。**

## 硬性规则
1. **只写自己的文件。** 只允许写 `round9/screens/<编号>.md` 和 `round9/status/<编号>.txt`，以及 `/tmp/round9_<编号>/` 下的临时文件。不改仓库里的其他任何文件。**不运行任何 git 命令**（避免多个智能体同时写仓库冲突；提交由主线执行者统一做）。
2. **不跑重计算。** 不用 GPU/MPS；单个命令 CPU 不超过 10 分钟；下载总量不超过 1 GB。需要大规模验证的，写进方案，等分派。
3. **不对外行动。** 不发邮件、不发帖、不开 issue 或 PR、不提交表单、不注册账号、不向 Codabench 或任何竞赛提交。只读网页和公开 API。
4. **数据红线。** 不碰 BioXArena xatlas 的基因身份；不使用 X-Atlas/Orion 或其衍生数据。
5. **文献必须核实。** 每篇引用都要用 arXiv API、bioRxiv API（api.biorxiv.org）、Crossref（api.crossref.org）、PubMed E-utilities 之一核实标题和作者，在输出里写明核实来源。核实不到的不写。禁止「XX Authors」。
6. **禁止「首次」「首个」「攻破」**，除非你的检索记录支持；即使支持，也写成「在我们检索的范围内未见」。
7. **不利信息照写。** 发现某个候选已被解决、部分解决或有直接竞争者，必须写出来并给出链接。

## 每个候选必须同时满足 5 条（缺一条就淘汰）
1. **权威来源说它没解决**：2025–2026 年论文、综述或竞赛官方页面的原话（≤30 字引文 + 链接）。
2. **查新为空**：近 24 个月，bioRxiv、arXiv、PubMed、Google Scholar、Nature/Cell/Science 系列、GitHub、竞赛榜单；列出检索词和命中文献。部分解决的写清楚别人做到哪、我们补哪。
3. **成败由外部判定**：公开测试集上的官方指标、提前公开带时间戳的预测、或精确证明加独立检查器。不接受自定义指标。
4. **本机可做**：一台 M3 Pro Mac（36 GB 内存，MPS，无 CUDA），全队同一时间最多 2 个重计算任务；单个候选的完整攻题不超过 3 天。
5. **不违反规则**：见上面第 3、4 条。

## 输出格式（`round9/screens/<编号>.md`）
1. 方向概述（3 句以内）。
2. 候选表：| 候选 | 开放性证据（原文+链接） | 查新结论 | 外部判定方式 | 算力估计 | 顶刊潜力（1–5 + 理由）| 主要风险 | 推进/淘汰 |
3. 至少 3 个候选；排名前 1–2 的写出：具体科学问题、预注册的成功判据、失败时能写成什么结果、需要的数据（来源、许可证、大小）。
4. 检索记录：检索库、检索词、日期、命中数、关键命中。
5. 文献核实表：引用 | DOI/arXiv/URL | 核实 API | 结果。
6. 末行单独写 `SCOUT_DONE`。

## 状态汇报
开始时、每完成一个候选、结束时，把一行状态覆盖写入 `round9/status/<编号>.txt`（例如 `S3 | 检索中 | 已筛 2/3 | 16:40`）。
