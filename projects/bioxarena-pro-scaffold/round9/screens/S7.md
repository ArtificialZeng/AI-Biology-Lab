# S7 选题筛查与查新报告：AI 科学家的元科学（以本项目为数据）

## 1. 方向概述

S7 方向依托本仓库 8 轮研发沉淀的 34 条主控审计台账（`reports/AUDIT_LEDGER.csv`）、自主性证据包（`reports/AUTONOMY_EVIDENCE.md`）及 54 个历史计算生物学审计项目，围绕「自主科学智能体的验证、跨厂商审计与失败机理」寻找**外部可裁决且文献尚未解决**的因果性元科学问题。2025–2026 年文献已完成大量单生成器审计基准与描述性失败分类（如 `CrossAudit` `arXiv:2608.28631`、`Dong 2026b` `arXiv:2611.23250`、`Song 2026` `arXiv:2610.01471`、`AutoResearchEval` `arXiv:2608.14905`、`Into the Unknown` `arXiv:2610.19159`），但在「对称 $2\times 2$ 匹配误报率与采样下的同厂商 vs 跨厂商审计真相」「闭环审计提升外部真实测试分还是仅抑制虚假宣称」「过程轨迹跨基准可预测性」三处仍存在清晰实证空白。经逐条核对 5 项准入条件，本报告**推进 3 项**（C1 与 C2 优先，C3 备选）、**淘汰 2 项**（与已有大规模文献重叠的 C4 及缺乏外部裁决的 C5）。

## 3. 排名前 1–2 候选的详细研究方案

### 排名 #1（首选推进）：C1 — 对称 $2\times 2$ 同厂商 vs 跨厂商审计的匹配误报率、盲区互补与修后外部测试分受控实验

1. **具体科学问题**
   在受控的对称 $2\times 2$ 厂商交叉设计（生成器 $G \in \{\text{Anthropic Claude}, \text{OpenAI GPT}\}$ $\times$ 审计器 $A \in \{\text{Anthropic Claude}, \text{OpenAI GPT}\}$，共 4 组配对，均强制新鲜上下文、同一推理预算与统一温度采样）下，**剥离模型强弱、采样随机度与告警阈值（操作点）混杂后**：
   - **(Q1a)** 跨厂商审计（$A \neq G$）在**相同误报率（matched FPR）**与自然多文件科研错误上，对同厂商审计（$A = G$）是否仍存在显著的真阳性检出率（ROC-AUC / TPR@FPR=5%、10%）优势，抑或此前观察到的「跨厂商领先」实为操作点偏移或模型个体能力差异？
   - **(Q1b)** 同厂商与跨厂商审计捕获的错误类别（如依据 `AUDIT_LEDGER.csv` 提炼的「统计独立性/划分泄漏」「硬编码/假阳性指标」「论文–代码不一致」）是否呈现**结构性正交互补**（不同厂商对不同缺陷家族的 Jaccard 分离度），以及这种互补是否转化为**一轮有限修复后的真实外部可执行测试分提升**？

2. **与本项目已有数据的衔接（严防数据泄漏）**
   - `reports/AUDIT_LEDGER.csv`（34 条干预：过度表述 12、数值不一致 10、流程治理 6、基线公平性 3、预注册/指标等价/混杂各 1）及 `AI-Biology-Lab` 54 个历史代码/数学审计项目仅用于**构建与冻结《科研审计规则手册（Constitution）》及确定性检查层（DCL）**，绝不作为评测集；所有评测均在完全独立的外部公开数据集上进行。
   - **规则红线坚守**：严格不读取或反匿名 `xatlas-orion-perturb` 基因身份，不向 Codabench 提交任何结果。

3. **预注册的成功判据（Pre-Registered Decision Criteria）**
   - **采样与操作点统一协议**：所有 $2\times 2$ 臂强制固定相同采样参数（如 $T=0.2$，每实例 $K=4$ 次独立读取），同时要求审计器按 4 级连续置信度/严重度（`CRITICAL` / `HIGH` / `MEDIUM` / `LOW` 或 0–100 分）输出，从而在**每条基线的实测 FPR 曲线上做精确 ROC 对齐**（主比较点锁定 $\text{FPR} \le 5\%$ 与 $\text{FPR} \le 10\%$）。
   - **主判据 H1（匹配 FPR 下的跨厂商净检测优势）**：在跨生成器汇总与各生成器分层内，计算配对差 $\Delta \text{TPR}_{\text{cross}-\text{same}}$（同一生成器产出的自然缺陷集上，跨厂商审计减去同厂商审计在 $\text{FPR}=10\%$ 处的检出率）及全曲线 $\Delta \text{AUROC}$。采用按任务/论文聚类的 10,000 次分层自助法 95% CI 与聚类符号翻转置换检验（Holm 校正 $\alpha=0.05$）：若 $\Delta \text{TPR@10\%FPR}$ 或 $\Delta \text{AUROC}$ 在两个生成源方向上均为正且 95% CI 严格排除 0，判定**支持跨厂商独立盲区假设**；若双方向均含 0 或出现厂商主效应（如某单一审计厂商在两组生成源上同时胜出），判定**推翻对称跨厂商假设，归因为模型能力/校准非对称**。
   - **主判据 H2（修后可执行外部测试分增益）**：将审计器在固定 $\text{FPR}=10\%$ 门槛下发出的 `BLOCKER` 反馈回原生成器进行 1 轮受控修复，以确定性外部执行测试通过率 / `grade.py` 分数增量 $\Delta S_{\text{cross}} - \Delta S_{\text{same}}$ 为终局外部指标（95% 聚类 bootstrap CI 与精确 McNemar 检验）。

4. **失败时能写成什么结果（Publishable Null / Boundary Outcomes）**
   - **若对称 $2\times 2$ 匹配 FPR 后跨厂商优势归零（仅存在单一模型家族主效应或操作点差异）**：可直接证伪 `CrossAudit` 核心前提（`I1` 厂商异质性本身并不产生超额检出），证明 `Dong (2026b)` 与 `Song (2026)` 观察到的差异源于单向生成器设计、温度不匹配与告警阈值差异，并给出「按审计能力选强审强而非盲目跨厂商配对」的新准则——这本身即是高影响力的元科学证伪结论。
   - **若检出率上升但修后外部测试分不升反降（修复回归 / Goodhart 效应）**：可定量刻画类似 `Bansal & Gangwani (ICML 2026)` 与 `Dong (2026b)` 观察到的「修复引入新缺陷」机制，定位语言审计何时失效、必须交由确定性检查（DCL）兜底。

5. **需要的数据（来源、许可证、大小，全部核实且总量 $< 1\text{ GB}$）**
   - **`SciCoQA`（真实论文–代码不一致基准）**：来源 `https://huggingface.co/datasets/UKPLab/scicoqa`（对应 [arXiv:2601.12910](https://arxiv.org/abs/2601.12910)）；许可证 `CC BY 4.0`；大小 **3.49 MiB**（`data/` parquet 合集，全仓 `3.67 MB`，包含 92 例真实科研论文–代码差异 + 543 例合成对照）。
   - **`BioXArena-Pro-Public` 非 `xatlas` 域 CPU 子集**：来源 `https://huggingface.co/datasets/mbzuai-ai4bio/BioXArena-Pro-Public`（对应 [arXiv:2611.13994](https://arxiv.org/abs/2611.13994)）；许可证 `CC BY-NC 4.0`（数据）+ 本地 `/Users/mac/BioXArena-Pro/tasks/` 官方 `grade.py`（`MIT License`）；大小：`chemical-biology-8tasks-all.tar.gz`（**273.55 MB**）+ `phenotype-disease-8tasks-all.tar.gz`（**313.70 MB**）= **587.24 MB**（约 `560.0 MiB`）。由 Anthropic 与 OpenAI 两种生成器分别生成自然科研建模解（含可自然触发的泄漏/口径/基线缺陷与正常解），在本地切分的生物单元外留集上运行官方 `grade.py` 给出零裁判真值标签。
   - **`SciCode-Verified` 题目与清洗日志（纯题目规格，不下载超大 HDF5）**：来源 `https://huggingface.co/datasets/shhu2001/SciCode-Verified`（对应 [arXiv:2608.04975](https://arxiv.org/abs/2608.04975)）；许可证 `Apache-2.0`；`data/` 题目集 **929.4 KB**（注：其全量测试集 `test_data_cleaned.h5` 为 **1,108,078,257 bytes ≈ 1.03 GiB**，超过 1 GB 红线，因此默认方案**不下载**该 HDF5，只用 `BioXArena-Pro-Public` 587 MB + `SciCoQA` 3.49 MB + `Matbench` 作为可执行真值基板；若后续主控单独特批扩展，再行考虑）。
   - **合计下载量**：**约 591 MB**（严格 $< 1\text{ GB}$）。
   - **前置资源需求**：需要主控与人类 PI 批准并配置跨厂商 API 密钥（如 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`）及约 800–1,600 次审计调用的 API 预算。

### 排名 #2（备选重点推进）：C2 — 闭环跨厂商审计+确定性契约能否提升真实科研基准外部测试分的四臂随机对照试验

1. **具体科学问题**
   在**总 token/时间预算与底层模型严格匹配**的端到端科研代理运行中，嵌入由本项目 `AUDIT_LEDGER.csv` 提炼的「跨厂商审计 + 确定性契约检查层（DCL）」，究竟是：
   - **(假设 A — 能力增益)** 能通过拦截泄漏、错误统计口径与有缺陷建模路径，迫使生成器转向更稳健方法，从而**实质提高**在未见外留测试集上的真实科学预测分数；还是
   - **(假设 B — 诚信–收益解耦 / 诚信刹车)** 无法显著提高甚至因堵死捷径而略微压低表面分数，其真正统计显著的因果收益集中于**消除「开发–外留泛化缩水（overfitting/leakage gap）」与消除无据夸大/虚假宣称（integrity failures）**？

2. **与本项目已有数据的衔接**
   - 本项目 Round 1–8 在 `AUDIT_LEDGER.csv` 中观察到：审计在 `GDSC` 上把虚高的 `0.1942` 压回 `0.1199`、在 `xatlas` 上撤回幸运切分 `0.0804` 并拒绝两项样本不足的第四数据集，但随后在外部 `Nadig 2025` 上实现预注册确认——然而本仓库仅有单一协作轨迹（$n=1$ 案例）。C2 将这一「诚信刹车 vs 真发现引擎」假说推广为可重复的多任务四臂 RCT。
   - **严守红线**：不运行 Codabench 提交，不使用 `xatlas` 或 `Orion` 数据。

3. **预注册的成功判据（Pre-Registered Decision Criteria）**
   - **四臂配对随机设计（每任务固定墙钟 15 分钟与等量迭代上限）**：
     - **Arm 0（无审计基准）**：单模型迭代直至预算耗尽。
     - **Arm 1（同厂商自审）**：同家族独立会话审计反馈 + 修复，匹配总调用预算。
     - **Arm 2（纯确定性检查 DCL-Only）**：仅运行非模型确定性契约脚本（泄漏检测、数字–日志溯源 `number→source`、基线/分组一致性检查、格式预检）反馈，无 LLM 审计。
     - **Arm 3（跨厂商审计 + DCL）**：`DCL` 先行硬拦截 + 异厂商 LLM 依据版本化规则手册（源自 `AUDIT_LEDGER.csv` 7 类缺陷）审计并给出 `BLOCKER` 修正。
   - **双主终点（Co-Primary Endpoints）**：
     1. **真实外留表现（Held-Out Score）**：`Matbench` 10 项任务官方 `fold-0` 外留测试指标（MAE 相对降低 / ROC-AUC）及 `BioXArena-Pro-Public` 4–6 项精选非 `xatlas` CPU 任务的生物单元外留 `grade.py` 分数，使用跨任务配对 Wilcoxon 检验与 10,000 次分层自助法 95% CI（比较 Arm 3 vs Arm 0、Arm 3 vs Arm 1、Arm 3 vs Arm 2）。
     2. **泛化膨胀与诚信违约率（Overclaim / Shrinkage Gap）**：每任务计算 $\Delta_{\text{inflate}} = \text{Score}_{\text{agent\_reported\_dev}} - \text{Score}_{\text{outer\_holdout}}$，以及确定性程序自动检验的数字不一致率、跨折/跨组泄漏率、无脚本来源宣称率（精确 McNemar / Fisher 检验）。
   - **判定规则**：仅当 Arm 3 在两项主终点之一相对 Arm 0 与 Arm 1 均在 Holm 校正后 $p < 0.05$（且 95% CI 排除 0）时，方可宣称对应因果效应成立。

4. **失败时能写成什么结果**
   - **核心解耦发现（极具顶刊价值）**：若试验确认 Arm 3 对「原始外留测试分」无显著提升（与 `Ríos-García et al. 2026` 脚手架方差仅 1.5% 一致），但将 $\Delta_{\text{inflate}}$ 与科研诚信违约率大幅压低（如降低 $\ge 50\%$），即可正式确立**「AI 科研审计的非对称价值定律」**：外部跨厂商审计不是免费提高模型上限的「算法炼金术」，而是防止科研泡沫、量化并收敛研究结果可信边界的必要**计量校准器（scientific metrological brake）**。

5. **需要的数据（来源、许可证、大小，全部核实且总量 $< 1\text{ GB}$）**
   - **`Matbench`（10 项 CPU 晶体/成分预测任务）**：来源 `https://github.com/materialsproject/matbench`（对应 [Dunn 等 2020](https://doi.org/10.1038/s41524-020-00406-3)，与 `Ning 等 2026` `arXiv:2607.17100` 同源的 CPU-only 10 任务子集）；许可证 `modified BSD`；数据包约 **~100–200 MB**（随 `matbench` 0.6 按任务按需拉取，远低于 1 GB）。
   - **`BioXArena-Pro-Public` CPU 子集**：`chemical-biology-8tasks-all.tar.gz`（**273.55 MB**）+ `phenotype-disease-8tasks-all.tar.gz`（**313.70 MB**，从中精选 4–6 项无 GPU 需求任务如 `solubility`、`tdc-dti-binding-affinity`、`gutcrc-cross-cohort-detection`、`msk-met-tumor-origin` 等），许可证 `CC BY-NC 4.0` + 官方 `grade.py`（`MIT License`）。
   - **本地规则先验**：`projects/bioxarena-pro-scaffold/reports/AUDIT_LEDGER.csv`（12.9 KB，`MIT License`）。
   - **合计下载量**：**约 700–800 MB**（严格 $< 1\text{ GB}$）。
   - **算力与前置条件**：M3 Pro Mac（36 GB RAM，无 CUDA）；需控制单次运行 $\le 15\text{–}20$ 分钟且只用 10–12 个 CPU 轻量任务以保证 $\le 3$ 天完成，同时需主控与人类 PI 批准多厂商 API 调用预算。
